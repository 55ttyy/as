# FOFA 自然语言查询转换任务集

本仓库保存一套 FOFA 自然语言资产搜索任务、对应的查询转换结果，以及参赛包资料和生成过程记录。题目覆盖 IP/CIDR、域名、端口、协议、HTTP 响应特征、TLS 证书、地理位置、ASN 和云服务等场景，也包含 Shodan、Google Dork、Hunter、Censys 查询迁移以及非法 FOFA 查询修正。

- 参赛包编号：`pkg-08e82c8d`
- 题目总数：100
- 分片方式：10 个任务文件，每个文件 10 题
- 当前分支：`main`

本仓库中的转换结果用于离线复核、批量维护和提交前校验，不代表官方参考答案；最终结果以比赛平台实际执行为准。

## 目录结构

| 路径 | 说明 |
| --- | --- |
| `q/task-01.md` 至 `q/task-10.md` | 按题号顺序拆分的任务文件，每份 10 题 |
| `anser/1.json` 至 `anser/10.json` | 与任务文件一一对应的查询结果，每份 10 题 |
| `tm/1.md` | 完整的 100 道题目，文件内容为 JSON 数组 |
| `tm/2.md` | 汇总后的 100 题查询结果，文件内容为 JSON 对象 |
| `tm/3.md` | 参赛包编号和发放时间 |
| `tm/4.md` | 比赛说明、答案规范和提交要求 |
| `as.bundle` | 可直接校验或克隆的 Git bundle 快照 |
| `codex-session-*.md` | 题目处理和仓库整理过程的会话记录 |
| `AGENTS.md` | 仓库维护与贡献规范 |

答案目录名为 `anser`，这是仓库当前采用的固定目录名。自动化脚本或提交流程接入时应保持该名称，或在迁移目录时同步修改所有引用。

## 答案格式

每个答案文件都保存完整的包裹对象，而不是单独的答案数组：

```json
{
  "选手名称": "",
  "参赛包编号": "pkg-08e82c8d",
  "答案": [
    {
      "题号": "M001-S009",
      "查询语句": "ip=\"20.247.40.92\""
    }
  ]
}
```

提交或合并答案时需满足以下约束：

- 答案中的题号必须与对应任务文件完全一致，不得缺题、重复或增加未知题号。
- 每道题只填写一条最终 FOFA Query，不附加解释、Markdown 或候选答案。
- Query 是一个 JSON 字符串，因此其中的双引号需要按 JSON 规则转义。
- 无法转换为 FOFA Query 的题目使用固定文本：`该需求不能直接转换为FOFA搜索语句`。
- 使用 UTF-8 编码；提交前应按比赛要求填写 `选手名称`。

例如，自然语言需求“请查询 IP 地址为 `20.247.40.92` 的资产”对应的查询为：

```text
ip="20.247.40.92"
```

多条件查询使用 FOFA 支持的字段、逻辑运算符和括号，例如：

```text
country="KR" && region="Gangwon-do"
(title="Jenkins" || body="jenkins") && country!="CN"
```

## 使用方式

1. 在 `q/task-XX.md` 中定位题号，阅读“自然语言输入”。
2. 在对应的 `anser/X.json` 中查找相同题号，检查或更新“查询语句”。
3. 需要汇总时，参考 `tm/1.md` 和 `tm/2.md` 的全量结构。
4. 提交前核对参赛包编号、题号覆盖范围、JSON 语法和 UTF-8 编码。

当前仓库没有需要编译的应用程序，也没有配置构建、测试、格式化或 lint 命令。日常验证以文件内容、JSON 解析、题号一致性和 Git 状态检查为主。

`as.bundle` 可使用标准 Git 命令验证和恢复：

```text
git bundle verify as.bundle
git clone as.bundle as-recovered
```

## 提交与维护

- 保持 `q/` 中任务顺序与 `anser/` 中答案顺序一致。
- 修改答案后检查所有 JSON 仍可解析，并确认没有残留的“待填写”或解释性文本。
- 不提交账号、密钥、访问令牌或未经授权的数据。
- 提交信息使用简洁的祈使句，例如 `Add README and validate answer layout`。

更完整的贡献、命名和评审约定见 [AGENTS.md](AGENTS.md)。
